# kikitori

kikitori は日本語の会議の録音を、話者ごとの発言（開始と終了の秒・話者番号・本文）に起こすコマンドです。文字起こし（`kikitori transcribe`）は手元の PC で動き、LLM を使いません。誤りを直す補正（`kikitori refine`）は、別の 2 つの音声認識の結果と LLM を使って本文を直します。

kikitori が出すのは起こした本文だけで、要約や整形はしません。要約や整形は、利用者に頼まれたときに、結果を受け取ったあなたが行います。

## 利用者が決めること

次のことは利用者の判断なので、依頼から読めなければ、実行する前に確かめます。

- **取得・インストール・更新・削除。** 数百 MB から最大約 27GB を取得し、PC に変更を加えるためです。何をどれだけ入れるか・消すかを `--dry-run` の出力で伝えて了承を得てから、`--yes` を付けて実行します。
- **本文を PC の外へ渡すこと。** `--external claude` と `--external bundle`（あなたが直す手順）は、本文と用語集を外部の LLM へ渡します。利用者が外部の LLM を使うと言ったときだけ使います。
- **管理者権限。** 権限が要る操作（終了コード 10）は、出たコマンドを利用者に実行してもらいます。あなたが権限を上げて実行すると、利用者の知らない変更が PC に入るためです。
- **会議の中身にかかわる指定。** 参加者の人数、英語の発言が多いか、補正を使うか、用語集に書く社名や製品名です。

## 実行の仕方

- 文字起こしは `kikitori transcribe <音声>` と実行します。`kikitori <音声>` でも動きますが、ファイル名がコマンド名（`doctor` など）と同じだとコマンドとして読まれるためです。
- 結果は stdout に、進み具合と警告は stderr に出ます。stderr を読むときは `--log-format json` を付けると、1 行 1 件の JSON（`type` は `progress`・`info`・`warning`・`error`・`summary`）になります。
- あなたの実行には TTY が無いものとして扱います。確認が要る操作は、TTY が無いと答えを待たずに終了コード 6 で止まります。
- `--dry-run` は何をするかを出すだけで、何も変えません。了承を得る前の説明に使えます。
- `--offline` は取得を止めます。モデルが足りなければ終了コード 5 で止まります。

## 基本の流れ

1. `kikitori --version` で、0.3.0 以上が入っているかを確かめます。無い、0.2.x が返る、または動かないときは、[references/install.md](references/install.md) に従います。Intel の Mac（`uname -sm` が `Darwin x86_64`）には対応していないので、インストールせずに、そのことを利用者に伝えます。
2. `kikitori transcribe 会議.m4a --num-speakers 4 --format json-v1 > 会議.json` のように起こします。人数は `--num-speakers` で渡します。渡さないと、話者を分けすぎたりまとめすぎたりするので、依頼から読めなければ利用者に聞き、利用者も分からなければ省きます。結果をあなたが読んで使うなら `json-v1` を、利用者がそのまま読むなら既定の `txt` を選び、保存先は利用者の指定に従います。
3. 固有名詞の誤りが目立てば、まず `--dict`（読みが一致した語を表記に置き換える辞書）を試し、直らなければ利用者に確かめて補正を使います（[references/refine.md](references/refine.md)）。

出力形式、辞書の書き方、日英混在の会議、Zoom の参加者ごとの録音、長い録音を先頭だけで試す方法は [references/transcribe.md](references/transcribe.md) にあります。インストール・更新・削除・スキルの書き込みは、どれも [references/install.md](references/install.md) の手順で行います。ファイルを手で消して取り外すと、PATH の行やモデルが残るためです。

## 出力の読み方

LLM や道具で読むときは `--format json-v1` を使います。`schema_version` と、発言の配列 `segments` を持つ形です（`kikitori schema transcript-v1` で JSON Schema が出ます）。各発言は次を持ちます。

- `start`・`end`：秒。
- `speaker`：0 から数える話者番号（txt の「話者1」が `0`）。人物名ではないので、名前との対応づけは結果を読む側が行います。
- `text`：本文。句読点は付きません（補正で LLM が突き合わせて直した本文には付きます）。

## 補正

`kikitori refine` は、文字起こしをやり直したうえで誤変換や取りこぼしを直します。手元の PC で直すとき、本文は外へ出ません。

- 先に `kikitori refine --plan --glossary 用語集.tsv` で、どう直すか（直し方）と使うモデルを見ます。音声は要りません。直し方が利用者の望みに足りるか分からなければ、利用者に確かめます。
- 本番は `--plan` を外し、`transcribe` と同じ `--num-speakers`・`--dict` を付けて実行します。付けないと、話者番号や区間の数が `transcribe` の結果と食い違います。
- 直し方は Ollama の有無、PC のメモリ、入っているモデル、`--glossary` の有無で決まります。LLM を使えないとき（Ollama が答えない、モデルが無いなど）も失敗にはならず、LLM を使わない直し方（長さの規則）に切り替えて終了コード 0 で終わります。選んだ直し方と理由は stderr（`--log-format json` では `info`・`warning`）に出るので、理由とともに利用者に伝えます。
- 補正は日本語だけです。`--model ja-en` を付けると終了コード 2 で止まります。

用語集の書き方、直し方の種類、モデルの選ばれ方、あなたが直す手順（`--external bundle`）、所要時間とメモリは [references/refine.md](references/refine.md) にあります。

## 診断

動かないとき、インストールの直後、補正の前は `kikitori doctor`（機械が読むなら `--json`）を実行します。OS、使える計算機（CPU・Metal・CUDA）、取得済みのモデル、ffmpeg と Ollama の有無、補正がどの直し方になる見込みか、空きメモリが分かります。

## 終了コード

`--log-format json` のとき、失敗は `type` が `error` の 1 行で出て、`code`・`message`・`hint`（次に実行するとよいコマンド）を持ちます。分岐は終了コードか `code` で行います。`hint` は、了承の要る操作（取得・インストール・更新・削除）でなければ、そのまま実行できます。

| コード | `code` | 意味 | 次の手 |
|---|---|---|---|
| 0 | `success` | 正常終了 | 補正が LLM を使わない直し方に切り替わったときも 0。stderr の警告を読む |
| 2 | `usage` | 引数の誤り | `--help` でオプションを確かめる |
| 3 | `input` | 入力が無い、読めない、形式が正しくない | パスと形式を確かめる |
| 4 | `dependency` | 要るソフトが無い | 多くは Opus の音声に要る ffmpeg。入れ方は `hint` に出る。入れるのは了承を得てから |
| 5 | `offline_model` | `--offline` でモデルが足りない | `--offline` を外すか、了承を得て `kikitori setup` |
| 6 | `needs_confirmation` | 確認が要る | 了承を得て `--yes` を付けて実行し直す |
| 7 | `download` | 取得の失敗（空き不足を含む） | 通信の失敗なら実行し直す（続きから再開する）。`hint` が空きの不足を言うなら、利用者に空けてもらう |
| 8 | `processing`・`internal` | 処理の失敗（`internal` は想定外の異常） | `-v` で理由を見る。直らなければ `kikitori doctor` の出力を利用者に見せる |
| 9 | `refine` | `--external claude` に要る `claude` コマンドが無い | 了承を得て Claude Code を入れるか、利用者がよければ `--external bundle` に替える |
| 10 | `privilege` | 管理者権限が要る | `hint` のコマンドを利用者に実行してもらう |
| 11 | `memory` | メモリが足りない見込み | `--dtype fp16` を付けて実行し直す。それでも足りなければ、了承を得て `--force` |

## 結果を渡すときの注意

- 固有名詞・数字・同音異義語は誤ることがあるので、前後の文脈で確かめてから使います。
- 重なった発言と、短い相づちは取りこぼします。
- 話者分離の精度は測っていません。話者の分け方が怪しいときは、そのことを利用者に伝えます。
